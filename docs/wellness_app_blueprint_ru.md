# Wellness-приложение: стартовый план (v0.1)

## 1) Цель продукта
Создать персонального ассистента по улучшению качества жизни, физического и ментального самочувствия, который:
- собирает исходные данные пользователя;
- проводит анкетирование и базовую оценку подготовки;
- выдает ежедневные персональные рекомендации;
- корректирует план на основе фактического выполнения и самочувствия;
- использует только рекомендации, основанные на научно подтвержденных подходах.

## 2) Платформы и технологический выбор
Чтобы покрыть **iOS + Android + ПК (Windows/macOS/Linux)** из единой кодовой базы:
- Рекомендуемый стек для MVP: **Flutter**
  - мобильные приложения: iOS/Android;
  - десктоп: Windows/macOS/Linux;
  - быстрый UI-прототип и единая логика.
- Backend (вариант для старта):
  - API: `FastAPI`;
  - БД: `PostgreSQL`;
  - фоновая логика рекомендаций: `Celery`/`RQ` (по мере роста).

## 3) Принципы "научно доказано"
Для каждой рекомендации хранить:
- `evidence_level`: A/B/C (сила доказательной базы);
- `source_type`: метаанализ / RCT / клиническое руководство;
- `source_link`: ссылка на источник;
- `contraindications`: ограничения и противопоказания.

Правила безопасности:
- исключать медицинские диагнозы и лечение (без статуса медизделия);
- показывать дисклеймер: приложение не заменяет врача;
- при тревожных симптомах рекомендовать обращение к специалисту.

## 4) Какие данные собираем на старте
### 4.1 Базовый профиль
- возраст;
- пол;
- рост;
- вес;
- семейное положение;
- уровень ежедневной активности (низкий/средний/высокий);
- цель (снижение жира, поддержание формы, рост выносливости, снижение стресса и т.д.).

### 4.2 Расширенный опрос
- сон: время отхода ко сну, время подъема, качество сна;
- стресс: субъективная оценка (например 1–10), источники стресса;
- питание: режим приемов пищи, вода, ограничения;
- ментальное состояние: энергия/настроение;
- желаемый процент жира, желаемые сроки цели.

### 4.3 Стартовые фитнес-тесты
- кардио: тест ходьбы/бега (время + дистанция + пульс при наличии трекера);
- силовые: максимум повторений для базовых движений (собственный вес / легкие веса);
- мобильность: простые тесты подвижности;
- RPE (ощущаемая нагрузка) после тестов.

## 5) Как формируются ежедневные рекомендации
Ежедневный план включает 4 блока:
1. **Сон**: целевое время сна и окно подъема;
2. **Движение/тренировка**: конкретные упражнения, подходы, повторы, интенсивность;
3. **Восстановление**: прогулка, дыхательная практика, медитация, растяжка;
4. **Поведение/фокус**: маленькая привычка дня (например 2 л воды, 15 минут без экрана перед сном).

### 5.1 Пример логики
- Если пользователь проснулся позже цели на >60 минут 2 дня подряд:
  - уменьшить утреннюю сложность;
  - сместить цель отхода ко сну постепенно (на 15–20 минут);
  - добавить короткую вечернюю рутину расслабления.
- Если тренировка отмечена как "слишком тяжело" (RPE 9–10):
  - снизить объем следующей тренировки на 10–20%;
  - добавить восстановительный день.
- Если 3+ дня подряд высокое настроение/энергия и выполнение 90%+:
  - плавно увеличить нагрузку (прогрессивная перегрузка).

## 6) Пользовательский цикл (ежедневно)
1. Утренний чек-ин (сон, самочувствие, стресс);
2. Получение плана на день;
3. Факт-ввод: что выполнено / насколько сложно / комментарий;
4. Вечерний чек-ин (энергия, настроение, время отбоя);
5. Пересчет рекомендаций на завтра.

## 7) Минимальный MVP (что делаем первым)
### Этап 1: Основа
- регистрация и профиль;
- базовый + расширенный опрос;
- стартовые тесты;
- генерация простого ежедневного плана по правилам.

### Этап 2: Обратная связь
- дневник выполнения;
- автоматическая адаптация нагрузки;
- визуальный прогресс (сон/вес/стресс/тренировки).

### Этап 3: Улучшения
- интеграции (Apple Health / Google Fit / Garmin / Zepp — позже);
- персонализация рекомендаций по паттернам поведения;
- библиотека научных источников прямо в приложении.

## 9) Метрики успеха
- удержание 7/30 дней;
- доля выполненных дневных рекомендаций;
- улучшение сна (регулярность подъема/отбоя);
- снижение субъективного стресса;
- рост тренировочной толерантности.

- получает персональный план на каждый день;
- может отметить факт выполнения и сложность;
- план на следующий день адаптируется автоматически;
- у каждой рекомендации есть `evidence_level` и источник.
